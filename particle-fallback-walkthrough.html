Before: WEBGPU-only. Any WEBGL run died at the first storage/compute call. Now: change one line to createCanvas(100, 100, WEBGL) and the same sketch runs on the CPU fallback.

Before: threw immediately

RendererGL had no createStorage. It threw WebGPU only. Your {position: Vector, velocity: Vector} array never got stored.

Diff: CpuStorageBuffer + inferCpuStructSchema

New CPU twin of the GPU buffer. Holds struct rows as plain JS objects, numbers in typed arrays. Infers schema {position: {dim:3, kind:'vector'}, velocity: {...}} from the first element. Sets duck-type flags _isStorageBuffer and _isCpuStorage so uniformStorage() accepts it. update/set/read validate shape with checkCpuStructShape and bump _cpuVersion.

Step 4 · compute(computeShader, 100) — line 24

src/strands/strands_jsBackend.js NEW (1161 lines) src/webgl/p5.RendererGL.js compute()

Before: no such path

RendererGL.compute did not exist or threw. Even if called, there was no _cpuIR and no JS compiler, so the recorded graph was already discarded.

Diff: compute() delegates to runCpuCompute(shader, x, y, z)

Resolves stores (calls function initializers, applies setUniform overrides) and scalars once. Compiles the compute hook once via compileCpuComputeHook() into fn(__idx, __s, __u, __v, H) with new Function, cached as shader._cpuComputeFn. Loops flat 0..99, maps flat -> (x,y,z), calls the fn with fresh locals {} each time. Warns past 4096 items but runs all. Bumps every bound store _cpuVersion after, since kernel writes touch raw arrays directly.

Now, for your kernel

Each invocation runs roughly: __s["data"].data[H.truncIndex(__idx[0])].position = H.binop(ADD, H.readFieldValue(...), H.readFieldValue(...)). H.readFieldValue converts stored p5.Vector to [x,y,z], math runs with GLSL semantics, H.writeFieldValue writes back into the same Vector. 100 iterations mutate the 100 objects in place.

Step 5 · buildMaterialShader(display) — lines 7, 15-21

src/webgl/strands_glslBackend.js +125 src/webgl/cpuStorageTexture.js NEW

Before: render shader could not see storage

GLSL backend emitted data[...] array syntax with no declaration behind it. Compile failed with undeclared identifier, or (earlier) a clear uniformStorage in render shader unsupported error. data[instanceID()].position had no translation.

Diff 1: declare each buffer as a data texture

uniform sampler2D data;
uniform int data_stride;

From addStorageBufferBindingsToDeclarations(). Only for shaders with vertex/fragment hooks. Compute-only shaders skip. WebGL1 errors clearly (needs texelFetch); compute still falls back.

Diff 2: reads become texelFetch

generateStorageRead() turns data[i].position into texelFetch(data, ivec2((t) % 256, (t) / 256), 0).rgb where t = i * data_stride + OFFSET. Your schema {position:vec3, velocity:vec3} gives offsets 0, 1, stride 2, so position is texel i*2 channels .rgb. Scalar int/uint reads get wrapped in int()/uint() via the Stop-3 arrayType field.

Diff 3: CpuStorageTexture uploads the bytes

Packs each p5.Vector via _getRGBA/components into RGBA32F, width 256, NEAREST filtering. getTexture(cpuBuffer) routes to this cache; _setCpuStorageLayoutUniforms uploads stride/count per draw so rebinding works. Re-uploads only when _cpuVersion changed. Disables premultiplied-alpha around upload.

Now

display compiles. data[instanceID()] reads the texel for that instance, .position selects the field offset, and worldInputs.position.xy += pos - center offsets each sphere.
